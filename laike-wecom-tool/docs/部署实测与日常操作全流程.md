# 部署、实测与日常操作全流程

适用配置：阿里云 Linux 服务器，1 vCPU、2 GiB 内存、5 Mbps；Windows 常开电脑运行企业微信及本工具发送端。以下采用 Ubuntu 24.04 LTS / x86_64 和 Docker Compose。现有系统不符合时，应使用对应系统的安装方式，保留已有业务。

本文是执行手册。当前已完成本机真实订单查询及用户确认的单条历史订单发送；尚未执行阿里云实机部署、DNS 修改或证书申请。每一步的通过标准用于部署时实际核对。

## 1. 准备信息与运行分工

| 信息 | 用途 |
| --- | --- |
| `SERVER_IP` | 服务器公网 IPv4；以下 SSH 示例用 `root` 登录，按实际账号替换 |
| `notify.example.com` | 实际使用的子域名，全文所有此域名都要替换 |
| `ADMIN_EMAIL` | HTTPS 证书联系邮箱 |
| `LAIKE_PROJECT_PATH` | Windows 上现有 `laike-wecom-tool` 的完整目录 |
| 现有后台密码 | 数据迁移后沿用；首次密码若未修改，在本机 `data/.bootstrap-password` 中 |

云端负责：抖音查询、门店匹配、模板、队列、后台、备份。Windows 负责：领取任务、操作已登录的企微、核对消息、回传结果。浏览器关闭不影响云端任务。Windows 关闭或桌面不可操作时，发送暂停；已生成的待发任务保存在云端。

部署路径固定为 `/opt/beauty-notification-service/laike-wecom-tool`；分支为 `feature/laike-wecom-tool`。以下 Linux 命令在服务器执行，PowerShell 命令在 Windows 执行。

## 2. 服务器、端口与子域名

在阿里云实例控制台核对系统、CPU、内存、公网 IP，并在安全组放行：

| TCP 端口 | 来源 | 用途 |
| --- | --- | --- |
| 22，或实际 SSH 端口 | 管理员实际公网 IP | 登录服务器 |
| 80 | 公网 | HTTP 跳转及证书申请 |
| 443 | 公网 | 后台与 Windows 发送端 HTTPS 连接 |

应用端口 `8790` 只绑定服务器 `127.0.0.1`，由 Nginx 转发。服务器内已有防火墙时，也需允许实际 SSH 端口和 80/443。依据：[阿里云安全组](https://help.aliyun.com/zh/ecs/user-guide/add-a-security-group-rule)。

在实际域名 DNS 管理后台新增：记录类型 `A`、主机记录 `notify`、记录值 `SERVER_IP`。保留现有 `www` 记录。用中国内地服务器对外提供域名访问时，先确认备案及阿里云接入状态。依据：[添加解析记录](https://help.aliyun.com/zh/dns/pubz-add-parsing-record)、[ICP备案](https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/what-is-an-icp-filing)。

Windows 检查解析：

```powershell
Resolve-DnsName notify.example.com -Type A
```

通过标准：返回的 A 记录是预期服务器公网 IPv4。

## 3. 安装服务器运行环境

通过阿里云 Workbench 或 SSH 登录服务器，执行 `sudo -i` 进入 root。先核对环境：

```bash
cat /etc/os-release
uname -m
free -h
df -h /
timedatectl
```

以下安装块只适用于 Ubuntu 24.04、`x86_64`。已安装可用的 Docker Engine 和 Compose 插件时，跳过 Docker 安装；已有 Nginx 网站或面板时，沿用其站点管理方式。

```bash
apt-get update
apt-get install -y ca-certificates curl git unzip nginx certbot python3-certbot-nginx dnsutils

install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

cat > /etc/apt/sources.list.d/docker.sources <<'DOCKER'
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: noble
Components: stable
Architectures: amd64
Signed-By: /etc/apt/keyrings/docker.asc
DOCKER

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker nginx
docker --version
docker compose version
```

Docker 软件源、GitHub、Docker Hub、Python 软件源下载失败时，应先核对服务器到该源的网络。代码获取及镜像下载成功后再继续。安装方式依据：[Docker Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/)。

## 4. 拉取程序，暂不启动

服务器执行。以下目标目录应为新目录；已存在同名部署时，应先核对现有数据和运行实例。

```bash
cd /opt
git clone --branch feature/laike-wecom-tool --single-branch https://github.com/Ghostisme/beauty-notification-service.git beauty-notification-service
cd /opt/beauty-notification-service/laike-wecom-tool
docker compose config --quiet
```

通过标准：克隆成功，Compose 检查没有错误。此时还未启动空白后台，下一步先迁移现有数据。

## 5. 暂停本机任务并备份现有数据

在当前 `http://127.0.0.1:8790` 登录本机后台：

1. “自动任务 → 数据同步计划”：关闭自动同步，点击“保存同步计划”。
2. “自动任务 → 通知发送规则”：关闭自动发送，点击“保存通知规则”。
3. 等待正在同步的任务结束，确认没有“发送中”或“等待回执”的任务。存在这类任务时，先核对其结果，再制作迁移备份。
4. 停止当前 Windows 发送端。前台运行时按 Ctrl+C；后台运行或计划任务运行时，在对应进程/任务中停止本项目实例。
5. 记录现有管理员密码。迁移备份不包含首次密码文本文件，云端不会重新生成已有用户的密码。

在 Windows 的项目目录执行：

```powershell
Set-Location 'LAIKE_PROJECT_PATH'
.\.venv\Scripts\python.exe -X utf8 manage.py backup

$laikeBackup = Get-ChildItem -LiteralPath '.\data\backups' -Filter 'laike-*.zip' |
    Sort-Object LastWriteTime -Descending |
    Select-Object -First 1
if (-not $laikeBackup) { throw '没有找到迁移备份' }
scp $laikeBackup.FullName 'root@SERVER_IP:/root/laike-migrate.zip'
```

SSH 使用指定私钥时，在 `scp` 后加 `-i '实际私钥文件路径'`。上述 `/root` 上传路径以 root 登录为前提；使用其他账号时，上传到该账号可写目录，再由服务器管理员移入部署目录。

备份包含同一时点的 `tool.db` 与 `.master-key`。它保留企业、门店、模板、同步游标、发送记录和加密凭证。本机的 `sender-config.json`、`sender-data/desktop-profile.json`、`sender-data/deliveries.db` 继续保留；它们分别是发送配置、校准与防重复账本。完成切换后，本机后台保持任务关闭并停止使用，由云端继续同步。

## 6. 恢复到服务器并启动后台

服务器执行，要求 `data` 中尚无另一套数据库：

```bash
cd /opt/beauty-notification-service/laike-wecom-tool
chmod 600 /root/laike-migrate.zip
unzip -l /root/laike-migrate.zip
install -d -m 700 data
unzip -q /root/laike-migrate.zip -d data
chown 10001:10001 data data/tool.db data/.master-key
chmod 600 data/tool.db data/.master-key

docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8790/health
docker compose exec -T tool python manage.py check
```

通过标准：容器正常运行，稍后显示健康状态；`/health` 包含 `"status":"ok"`；数据库检查正常。此时自动同步和自动发送沿用备份中的关闭状态。

首次镜像构建会下载基础镜像和依赖。部署已限制应用为 384 MiB / 0.8 核，镜像构建本身不受这两个运行限制约束。

迁移后的账号仍为 `admin`，密码沿用本机。仅在全新空白初始化时才从服务器 `data/.bootstrap-password` 读取新密码；空白初始化不会自动拥有本机配置。

## 7. 配置 HTTPS 后台入口

以下以系统 Nginx 为例。已经由宝塔、1Panel 等管理网站时，在面板新增这个子域名站点，反向代理到 `http://127.0.0.1:8790` 并申请证书。

使用系统 Nginx 时，先将下面的 `notify.example.com` 替换为实际子域名，再执行：

```bash
cat > /etc/nginx/conf.d/laike-notify.conf <<'NGINX'
server {
    listen 80;
    server_name notify.example.com;
    client_max_body_size 2m;
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 512;
    location / {
        proxy_pass http://127.0.0.1:8790;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_connect_timeout 5s;
        proxy_read_timeout 35s;
    }
}
NGINX

nginx -t
systemctl reload nginx
certbot --nginx -d notify.example.com --redirect --agree-tos --email ADMIN_EMAIL
nginx -t
curl --fail https://notify.example.com/health
certbot renew --dry-run
systemctl list-timers --all certbot.timer
```

证书申请依赖 DNS 已指向服务器且公网 80 可达。以上过程先建立 HTTP 站点，再由 Certbot 配置 HTTPS 及跳转，避免引用尚不存在的证书。续期检查成功且存在续期任务后，后续由该任务维护证书。依据：[Certbot Nginx 与续期文档](https://eff-certbot.readthedocs.io/en/stable/using.html)。

浏览器打开 `https://notify.example.com`，用原管理员密码登录。右上角应显示“正式环境”；企业、门店、模板、已发送记录与本机一致。迁移前的历史联调消息应仍为已发送。程序正式部署启用安全 Cookie，登录使用 HTTPS。

## 8. 从云端验证抖音和门店配置

1. 把服务器访问抖音时的实际公网出口 IP 加入抖音应用服务器白名单。直连通常对应实例公网 IP；有 NAT/代理时按实际出口核对。
2. 云端后台“接入设置 → 真实接入检查 → 验证应用凭证”，应显示已就绪。
3. 对已迁移企业点击“验证订单权限”，应成功。时间窗内 0 条订单是有效空查询，不表示已经验证了所有业务字段。
4. “企业与门店”中核对实际 `account_id`、`poi_id`、门店名称、群名和启用状态，全部以字符串形式保留原 ID。
5. 当前真实测试门店保持绑定 `壹心-湖南-测试消息店`；无需创建模拟企业或解除这条真实绑定。
6. “接入设置 → 企微外部群发送”选择“Windows 企微发送端”。HTTP 发送地址和 HTTP 接入令牌无需填写。

通过标准：真实应用和商户订单查询均成功，当前测试门店绑定正确。出现 `2119013` 时核对云端实际出口白名单；`2119005` 核对商家授权；`2190004` 核对订单查询能力。实际接口依据：[抖音生活服务订单查询](https://partner.open-douyin.com/docs/resource/zh-CN/local-life/develop/OpenAPI/general-capabilities/order.query/query)。

## 9. 让当前 Windows 发送端连接云端

先确认旧发送端已经停止。在 Windows 项目目录执行以下命令，只更新后台地址，保留令牌、发送身份和账本路径：

```powershell
Set-Location 'LAIKE_PROJECT_PATH'
$laikeConfigPath = Join-Path (Get-Location) 'sender-config.json'
$laikeConfig = Get-Content -LiteralPath $laikeConfigPath -Raw -Encoding UTF8 | ConvertFrom-Json
$laikeConfig.server = 'https://notify.example.com'
[System.IO.File]::WriteAllText(
    $laikeConfigPath,
    ($laikeConfig | ConvertTo-Json -Depth 10),
    [System.Text.UTF8Encoding]::new($false)
)

Start-Sleep -Seconds 4
.\.sender-venv\Scripts\python.exe -X utf8 sender.py --check --test-only
```

暂停键鼠约 4 秒后检查，避免刚输入命令导致“键鼠忙碌”。通过标准为 `server_connected: true`、`ready: true`。同一数据库迁移会保留发送端令牌；若云端是全新数据库，则从云端后台查看新令牌，运行 `sender.py --configure --test-only` 配置连接。

Windows 和企微仍保持原尺寸及缩放时，保留原校准即可。窗口或缩放改变时重新校准：

```powershell
.\.sender-venv\Scripts\python.exe -X utf8 sender.py --calibrate
```

五步依次为：搜索输入点、搜索结果中的完整群名和人数、顶部群标题、消息输入点、消息历史区。标题区与消息区分开；搜索结果排除“外部”标签和时间。选错可点“上一步”。

启动常驻发送端：

```powershell
.\.sender-venv\Scripts\python.exe -X utf8 sender.py --test-only
```

保持该窗口运行。云端“接入设置 → 真实接入检查”应显示发送端在线且覆盖测试门店群。由于自动发送关闭，此时不会领取通知发群。

## 10. 用真实数据逐项验收

迁移检查与业务验收分开记录。当前群已绑定真实测试门店，“测试消息”入口会引导真实接入检查；不应使用模拟配置覆盖真实门店。之前那条历史订单已发送过，保持原记录即可。

### 10.1 真实新订单：先人工核对，再发送

1. 保持自动发送关闭，在“自动任务”点击“立即同步一轮”，等任务完成，建立当前基线。
2. 在已授权的测试店完成一笔新的真实支付，记下订单编号、支付时间、套餐、数量和实付金额。
3. 再点击“立即同步一轮”。在“通知记录”找到该订单，核对只有一条新订单通知，门店、群名、金额和套餐正确。
4. 打开通知详情核对正文；手机号未返回时保持省略，不能把缺失值视为完整号码验证通过。
5. 确认待发队列中是计划发送的消息，发送端范围仍限测试群，再在“自动任务”开启自动发送并点击“保存通知规则”。
6. 暂停键鼠，让发送端搜索并发送。核对群内消息与订单编号，以及后台已发送、尝试次数和发送端回执。
7. 关闭自动发送，再同步同一订单两轮，确认未增加同一次支付的通知，也未在群内重复发送。

通过标准：真实新支付生成一条正确通知，准确进入测试群，后台收到发送端结果，重复同步不产生重复通知。客户端 OCR 确认与腾讯服务端送达凭证属于不同证据，当前实现使用前者。

### 10.2 自动任务：验证无需手动同步

在测试群完成上一项后：

1. “自动任务”开启自动同步，间隔填 `2` 分钟，保存。
2. 开启自动发送并保存；发送端继续限定测试群。
3. 再产生一笔新的真实支付，这次不点击立即同步。
4. 观察下一轮定时任务、通知生成和群内消息，记录付款、入队和发送完成时间。
5. 检查定时任务成功、通知只生成一次，群内只收到一次。

120 秒是查询计划间隔，整体延迟还包含接口查询、排队、桌面搜索及消息核对；它不是逐条消息的固定送达时限。

### 10.3 真实状态变化

“通知模板”启用状态变化模板；“自动任务 → 通知发送规则”勾选需要的核销、退款、取消等事件。先同步待测试订单建立变化前快照，再在来客按实际业务完成对应操作，随后等待下一轮查询。

每种计划启用的事件分别核对：真实状态确实变化、消息中的原状态和当前状态正确、订单编号正确、目标群正确、只生成一次。订单“已完成”本身不会自动当作已核销；程序按券履约状态识别。轮询可能错过快速连续发生的中间状态，需要完整事件时须接入实际事件源。

### 10.4 多门店路由

至少两家已授权真实门店分别绑定各自的唯一完整群名，发送账号加入两群。测试期间明确限定发送端范围。两店各完成一笔真实订单，分别核对各自订单只进入对应门店群。

单店样本可以证明该店匹配正确，不能代替两家门店之间的实际分流验收。

### 10.5 客户手机号与独立留资

已查询的历史样本没有客户称呼、手机号或可解密号码，完整号码权限尚未验证。新的真实订单若返回号码，再对照客户资料和授权范围检查。解密适配需用实际权限和接口合同验证后启用。

独立留资的模板、接入口和手工录入已存在，但自动从抖音取得独立留资的上游尚未接通。完整验收要求实际来源提供商户 ID、门店 ID、稳定留资编号、时间及内容，映射后调用 `POST /api/ingest`。使用相同编号重传应去重，实际通知应进入对应门店群。格式见 [接入说明](接入说明.md)。

后台“手工录入留资”可验证录入、模板和发送；该操作不证明已自动获取抖音留资。

### 10.6 人工介入与异常恢复

| 情况 | 操作与通过标准 |
| --- | --- |
| 暂停自动发送 | 新通知继续入队，群内不新增；恢复后处理待发队列 |
| Windows 发送端停止 | 云端继续同步；后台随后显示发送端离线；重启发送端后恢复处理 |
| 最小化、锁屏或键鼠忙碌 | 发送端报告不可操作原因；恢复桌面状态后重新就绪 |
| 待分配门店 | 查看订单和所属企业，在通知详情分配到该企业内正确门店，再核对正文和群 |
| 已明确失败 | 修正原因，重新加入发送队列，核对新尝试结果 |
| 待核实 | 先到对应群按订单编号核对；已发则人工确认，确认没发才补发 |

明确的失败会按配置重试；结果不明不会盲目自动重发。人工确认与发送端确认在后台分别记账。

## 11. 在这台云服务器实际测资源

### 11.1 观察正式服务

在服务器执行，观察空闲、真实同步、真实发送三种时段：

```bash
cd /opt/beauty-notification-service/laike-wecom-tool
free -h
df -h /
docker compose ps
docker stats --no-stream
docker inspect --format 'restarts={{.RestartCount}} oom={{.State.OOMKilled}} memory_limit={{.HostConfig.Memory}} cpu_limit={{.HostConfig.NanoCpus}}' "$(docker compose ps -q tool)"
docker compose logs --tail=100 tool
```

检查：没有 OOM 或持续重启；一轮正常同步能在当前计划间隔内完成；待发任务不会在正常业务量下持续积压；后台页面正常响应。CPU 查询时短暂升高与长时间持续满载应分开观察。至少覆盖正常时段和真实业务高峰，再决定是否扩容或分配更多发送电脑。

### 11.2 可选的隔离资源测量

该项用独立临时数据库生成合成任务，测入库及入队，不调用抖音、不操作企微，不写正式数据库，也不替代第 10 节的真实业务验收。建议在低峰执行。

服务器执行：

```bash
cd /opt/beauty-notification-service/laike-wecom-tool
apt-get install -y python3-venv
python3 -m venv /opt/laike-benchmark-venv
/opt/laike-benchmark-venv/bin/pip install -r requirements.lock psutil
/opt/laike-benchmark-venv/bin/python scripts/benchmark.py --count 1000 --output /root/laike-cloud-benchmark.json
cat /root/laike-cloud-benchmark.json
```

输出实际系统、逻辑 CPU 数、进程树内存、耗时、接口响应及数据库大小。`cpu_limit_applied=false` 表示脚本没有额外施加 CPU 配额；它运行在宿主机，不能当作 Compose 0.8 核 / 384 MiB 容器内的压测。正式容器的资源按上一小节单独观察。

## 12. 扩展到正式门店及登录后启动

每家企业先完成商家授权，在“企业与门店”添加根账户；其下添加各门店 `poi_id` 与唯一完整群名。需要的三类模板分别启用，状态事件另外勾选。门店名称按实际业务填写。

发送端在试运行期间继续限测试群。准备正式发送时，停止发送端，在 `sender-config.json` 中维护明确的 `group_names` 数组，加入负责的全部正式群名，再以普通模式启动：

```powershell
.\.sender-venv\Scripts\python.exe -X utf8 sender.py
```

示例范围字段（合并进已有配置，不覆盖令牌及其他字段）：

```json
{
  "group_names": [
    "壹心-湖南-测试消息店",
    "玥笙-辽宁-大连中山店",
    "壹心-湖南-长沙开福店"
  ]
}
```

运行时带 `--test-only` 会强制只处理测试群。`group_ids` 与 `group_names` 若同时设置，取两者交集；使用群名管理范围时先核对现有 `group_ids`，避免旧限制排除新门店。多台电脑应设置不同 `worker_id`，分别负责明确的群范围，每个 Windows 桌面只运行一个发送端。

登录后启动前，将当前负责范围写入配置文件，停止手动运行的旧实例，再以管理员身份打开 PowerShell，在 Windows 项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\install-sender-task.ps1
Start-ScheduledTask -TaskName 'Laike-WeCom-Sender'
Get-ScheduledTask -TaskName 'Laike-WeCom-Sender'
```

该计划任务按配置文件运行，不自动附加 `--test-only`；测试阶段配置中必须保留测试群限制。任务在当前用户登录后运行，仍需要 Windows 未锁定及企微已登录。配置后在云端核对发送端在线和负责群范围。

## 13. 每天如何操作后台

| 页面 | 操作 |

## 14. 每日备份、更新与恢复

手动备份与完整性检查：

```bash
cd /opt/beauty-notification-service/laike-wecom-tool
docker compose exec -T tool python manage.py backup --retain 7
docker compose exec -T tool python manage.py check
```

备份位于宿主机 `data/backups`，包含数据库及配套密钥，保留最近 7 份。需要长期保留的备份复制到另一处存储；Windows 的配置、校准和发送账本另行保留。

每日自动备份，以下时间按服务器本地时区执行，先用 `timedatectl` 核对：

```bash
cat > /etc/cron.d/laike-wecom-backup <<'CRON'
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
30 3 * * * root cd /opt/beauty-notification-service/laike-wecom-tool && /usr/bin/docker compose exec -T tool python manage.py backup --retain 7 >> /var/log/laike-wecom-backup.log 2>&1
CRON
chmod 644 /etc/cron.d/laike-wecom-backup
systemctl enable --now cron
```

更新前在后台暂停同步与发送，等待当前操作结束，停止 Windows 发送端并备份。服务器执行：

```bash
cd /opt/beauty-notification-service/laike-wecom-tool
docker compose exec -T tool python manage.py backup --retain 7
cd /opt/beauty-notification-service
git pull --ff-only origin feature/laike-wecom-tool
cd laike-wecom-tool
docker compose up -d --build
curl --fail http://127.0.0.1:8790/health
docker compose exec -T tool python manage.py check
```

Windows 端更新同一分支源码并保留本机配置与账本。健康、路由、发送端范围核对后再恢复自动任务。

恢复备份时：先暂停两端任务并停止云端容器；保留当前数据目录，恢复同一备份中的数据库与密钥；恢复 10001 用户权限；先保持自动发送关闭启动，检查数据库、待发及待核实记录。恢复旧备份后要结合本机账本和群内订单编号核对可能已发送的任务。更多恢复细节见 [阿里云部署和维护](阿里云部署.md)。

## 15. 常见问题定位

| 现象 | 先检查 |
| --- | --- |
| 域名无法访问 | A 记录、安全组、服务器防火墙、备案接入、Nginx 是否运行 |
| HTTPS 证书申请失败 | 实际域名、DNS 指向、公网 80 可达、证书错误原文 |
| 502 | `docker compose ps`、应用日志、代理目标是否 `127.0.0.1:8790` |
| 登录后仍回到登录页 | 使用 HTTPS、迁移后沿用原密码、会话是否因修改密码失效 |
| 抖音 `2119013` | 当前云端真实出口 IP 的应用白名单；不要沿用本机或另一条代理线路的 IP |
| 查询成功但 0 条订单 | 查询窗口内是否有实际新增或修改，不能据此认为所有字段和事件都验收通过 |
| Windows 连接失败或 401 | 云端 HTTPS 地址及发送端令牌，是否用了空白云库产生的另一令牌 |
| 发送端在线但不可用 | 后台显示的桌面原因、窗口尺寸、键鼠忙碌、校准、群范围 |
| 有新门店但不发 | 企业/门店启用、群绑定、模板/事件、自动发送、发送端是否仍为 test-only 或旧范围 |
| 已完成订单没有核销通知 | 实际券履约状态、变化前快照、事件开关；订单已完成不等同核销 |
| 手机号缺失 | 实际接口返回与权限、解密是否具备合同和真实验证；不能从空值恢复号码 |
| 独立留资仍待接入 | 实际上游来源尚未连接；手工录入和标准接入口本身不能证明自动获取 |

| 异常与维护 | 暂停恢复、发送端恢复、待核实处理、备份和检查 |
