# 壹心测试群联调

测试群完整名称：**壹心-湖南-测试消息店**。

这是专用测试群。后台会创建“壹心 · 测试专用”企业及对应测试门店，标记为测试用途，使用内部测试标识，无需提供真实抖音商户或门店 ID。自动同步会跳过这家测试企业，真实订单和留资接入也不能写入其中。

## 1. 配置测试群

登录后台，在“运行概览”点击“测试消息”，再点击“配置此测试群”。这一步只创建测试配置，不会创建或发送通知，也不会开启自动同步或自动发送。重复配置会返回同一条测试群绑定。

“企业与门店”会显示该测试配置及“测试专用”标记。测试群的程序逻辑 ID 固定为 `test-wecom-yixin-hunan`；这是程序内部标识，不是腾讯提供的 `chat_id`。

## 2. 只让 Windows 发送端处理这个测试群

在发送电脑安装 Python 3.12，安装发送端依赖，运行配置命令：

```powershell
python -m venv .sender-venv
.\.sender-venv\Scripts\python.exe -m pip install -r requirements-sender.lock
.\.sender-venv\Scripts\python.exe sender.py --configure --test-only
.\.sender-venv\Scripts\python.exe sender.py --calibrate
.\.sender-venv\Scripts\python.exe sender.py --check --test-only
```

配置时填写当前后台的 HTTPS 地址及发送端接入令牌。`--configure --test-only` 会把领取范围保存为这个测试群。令牌只在发送电脑填写，不提交到 GitHub。

发送账号需要已加入 `壹心-湖南-测试消息店`，企微保持登录、展开窗口，并完成界面校准。每个 Windows 桌面只运行一个发送端。已有其他发送端进程或计划任务时，先停止那个实例，再启动测试实例。

只领取一条任务并退出：

```powershell
.\.sender-venv\Scripts\python.exe sender.py --test-only --once
```

连续处理本测试群的任务：

```powershell
.\.sender-venv\Scripts\python.exe sender.py --test-only
```

运行时添加 `--test-only` 也会限制已有配置的领取范围，不修改配置文件。恢复正式门店发送时，重新运行 `--configure` 设置正式发送范围。

## 3. 创建并核对三类测试通知

在后台“测试消息”中选择：新订单、新留资或状态变化（模拟核销），点击“创建测试消息”。正文会带有 `【发送链路测试｜模拟数据】`，客户与团购项目为模拟内容，编号以 `TEST-` 开头，不包含真实客户手机号。

新订单示例：

```text
【发送链路测试｜模拟数据】
【抖音来客｜新订单通知】
门店：壹心-湖南-测试消息店
客户：测试客户（模拟）
团购项目：测试团购套餐（模拟）
购买数量：1
实付金额：¥0.01
订单状态：已支付（模拟）
下单时间：创建测试时的时间
订单编号：TEST-自动生成
```

新建通知先进入队列。确认接收群及正文后，在“自动任务”开启自动发送，并运行只领取测试群的发送端。该通知类型的模板需要启用。

在群里确认收到，同时核对后台通知详情的接收群、测试标记、状态和发送尝试。只看到本地客户端消息不能代表取得腾讯服务端的送达凭证；结果不明确时，先在群内核实再补发。

## 4. 测试范围

这一步验证“后台生成模板 → 队列 → Windows 企微发送端 → 专用测试群 → 后台结果”。真实抖音拉单、字段权限和实际门店路由，需要随后用已授权的真实企业与门店单独联调。

离线演示模式可以配置并预览这套流程，但不会向实际企微群投递。
