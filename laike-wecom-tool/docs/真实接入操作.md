# 本机真实接入

域名和阿里云部署可以稍后进行。先在一台已登录企业微信的 Windows 电脑运行正式后台和发送端，直接连接真实抖音应用及已授权商家。

## 正式后台

在 `laike-wecom-tool/` 中双击 `start-server.bat`，打开 `http://127.0.0.1:8790`。管理员账号 `admin`，首次密码在 `data/.bootstrap-password`。页面右上角应显示“正式环境”。

正式数据库为 `data/tool.db`，不会自动导入示例企业、门店、订单或成功发送记录。`start-demo.bat` 是单独的离线演示入口，不用于真实接入。

## 应用凭证及商家授权

1. 在后台“接入设置”填写真实服务商应用的 Client Key / Client Secret，保存。
2. 在同页的“真实接入检查”点击“验证应用凭证”。程序实际请求抖音令牌接口，返回成功才显示已就绪。
3. 在“企业与门店”添加真实根商户账号 ID（`account_id`），以字符串保存，避免大整数精度损失。
4. 回到“真实接入检查”，点击该企业的“验证订单权限”。程序真实查询最近 30 分钟最多 5 条订单，不推进同步位置，不生成通知，只记录样本数量与可用字段数量，不保存样本中的客户资料。

应用凭证验证成功和商家订单查询成功是两个环节。空订单数组只证明查询成功，不代表已经验证手机号、套餐或门店字段。凭证、接口配置变更后，旧检查会失效；超过 24 小时的检查显示待验证。

常见实际错误：

| 错误码 | 处理方式 |
| --- | --- |
| `2119013` | 在服务商应用的服务器 IP 白名单中添加实际查询电脑／服务器的公网出口 IP。地址应对应运行后台的网络，不能填写 `127.0.0.1`；迁移到阿里云后改用云端出口 IP |
| `2190004` | 应用尚未获得订单查询能力。开放平台应用详情的“解决方案”中申请 `life.capacity.order.query` |
| `2119005` | 商家尚未授权该应用。让商家在来客后台发起授权，并在服务商后台同意授权 |

接口与订单查询权限依据：[抖音生活服务订单查询](https://partner.open-douyin.com/docs/resource/zh-CN/local-life/develop/OpenAPI/general-capabilities/order.query/query)。

## 真实测试店与企微群

1. 使用真实测试店的 `poi_id` 添加门店，填写完整接收群名，例如 `壹心-湖南-测试消息店`。
2. Windows 模式使用程序生成的逻辑群标识；它与抖音的门店 ID、腾讯的群 ID 是不同字段。
3. 当前这台电脑既运行后台又运行发送端时，服务器地址为 `http://127.0.0.1:8790`。发送端令牌在“接入设置 → Windows 发送端连接”查看。
4. 运行 `start-test-sender.bat`，完成五步企微界面校准。该入口通过完整群名限制发送范围，可以匹配模拟测试配置，也可以匹配绑定了相同测试群的真实测试门店。
5. 没有匹配接收群时发送端不会领取任务；空群范围不会扩大为所有门店。

分步检查命令：

```powershell
.\.sender-venv\Scripts\python.exe sender.py --check --test-only
```

输出 `server_connected: true` 表示实际连接后台成功；`ready: true` 表示桌面及接收范围就绪。检查命令只读取群配置并上报心跳，不发送消息。

绑定了真实测试店的群用于接收真实订单。无需另建模拟企业或把真实商户填入模拟测试配置。订单接口验证成功后，在“运行概览”执行“立即同步”，先核对生成通知的接收群与正文，再启用自动同步、自动发送。

## 手机号、独立留资和状态变化

手机号以实际响应和权限为准。未返回、仅脱敏或尚未完成解密的号码会如实处理；界面不会凭空补出完整号码。接入检查仅统计本次样本中可用号码数量，不执行额外解密。

独立留资仍需确认真实的抖音留资能力、上游来源和字段。本工具的标准接收接口 `POST /api/ingest` 可以接收上游实际获得的数据，手工录入也可生成通知；这两项本身不能证明已实现自动从抖音取得独立留资。因此“真实接入检查”会保留该环节待接入状态。

状态变化通过真实订单与券状态的前后快照触发。核销、退款、取消分别启用，首次读取的历史状态不会伪装成刚发生的变化。正式通知的实际发送确认、测试通知确认和人工确认分别统计。

## 正式界面检查

`scripts/browser-live-check.cjs` 对运行中的正式实例执行只读界面检查，覆盖六个页面、真实接入状态、HTTP 字段切换及实际连接地址。结果和截图默认保存到被 Git 忽略的 `data/`，不会创建业务数据或发消息。它与针对合成数据的 `scripts/browser-check.cjs` 分开运行。
