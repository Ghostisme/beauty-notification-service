# Windows 企微发送端

云端保存任务和监控状态；Windows 端通过 HTTPS 拉取属于它所负责门店的任务，在企业微信桌面客户端中操作。

## 电脑与账号

- Windows 10/11、Python 3.12，企业微信桌面客户端。
- 发送账号已经加入需要接收通知的外部群。
- 群名完整且唯一。例如 `玥笙-辽宁-大连中山店`、`壹心-湖南-长沙开福店`。
- 使用常开、可交互、未锁定的桌面。锁屏、最小化、窗口尺寸改变、键鼠忙碌时发送端停止领取新任务。
- 校准后保持企微窗口尺寸和显示缩放设置一致。不要同时在这台电脑上执行其他键鼠自动化。

云端的 1 核 2 GiB 配置承担服务端；Windows 端的桌面及 OCR 开销在这台发送电脑上。本程序不会自动登录 Windows 或替你保存 Windows 登录密码。

## 安装和连接

双击项目根目录中的 `start-sender.bat`。首次安装会下载 OCR 运行库及自带模型。填写：

1. 后台的 HTTPS 地址，如 `https://notify.example.com`。
2. 后台“接入设置 → Windows 发送端连接”中查看的接入令牌。

这些信息保存在本机 `sender-config.json`。一个示例配置如下，令牌需在本机填写，不要将该文件提交到源码仓库：

```json
{
  "server": "https://notify.example.com",
  "token": "在本机填写后台发送端接入令牌",
  "worker_id": "windows-wecom-1",
  "label": "门店通知发送电脑",
  "data_dir": "sender-data",
  "profile": "sender-data/desktop-profile.json",
  "poll_seconds": 3
}
```

如多台发送电脑分别负责不同门店，给每台设置唯一 `worker_id`，再添加 `group_ids` 数组，仅填写这台电脑负责的逻辑群 ID。不要让多个自动化实例共同操作一个 Windows 桌面。

## 界面校准

运行 `sender.py --calibrate` 后，校准工具会显示当前企微主窗口截图。依次点击或框选：

1. 全局搜索输入框的位置。
2. 搜索结果显示的区域：只框完整群名所在结果列表，不包含输入框。需要覆盖客户端搜索弹出后显示群结果的位置。
3. 当前聊天的群标题区域：只框群标题及可能存在的成员数。
4. 消息输入框内的位置。
5. 聊天消息历史区域：包含发送后消息气泡，排除输入框，避免将尚未发送的草稿当成已发消息。

最后选择客户端实际使用的发送快捷键：Enter 或 Ctrl+Enter。校准只读取截图和保存坐标，不发送消息。

```powershell
.\.sender-venv\Scripts\python.exe sender.py --check
```

该命令检查桌面状态。运行发送端后，后台会显示心跳、就绪情况和相关原因。群绑定列表每 60 秒刷新；没有新任务时领取频率逐步放缓至最多 15 秒一次，使用持久连接减少流量。

## 第一条测试

1. 在后台配置一个测试门店及测试群，保持正式业务门店停用或将发送端 `group_ids` 限制为测试群。
2. 后台点击“测试消息”，选择这个测试门店。
3. 开启自动发送，在发送电脑观察一次操作：搜索群 → 精确匹配群名 → 进入群 → 核对群标题 → 粘贴 → 发送 → 检查消息。
4. 同时核对后台“通知详情”的接收群、正文、状态和尝试记录。
5. 若未能正确定位界面，暂停自动发送，重新校准后再处理这条通知。

保持模板中的 `订单编号：{订单编号}` 或 `留资编号：{留资编号}`。默认模板的业务时间和状态变化行也参与确认。OCR 不做群名或订单号的错字模糊匹配；不能完整识别时留下待核实记录。

## 结果如何记账

发送前，本机账本先写入“准备”，在按发送键之前提交“发送中”。确认后写入结果并上报云端。

| 本机情况 | 云端处理 |
| --- | --- |
| 在点击发送前失败，确认没有发出 | 按失败重试规则处理 |
| 点击发送后断线或不能完整识别消息 | 待人工核实，不自动重发 |
| 已识别目标群及消息，但回执上报失败 | 重报同一次结果，账本阻止重复按发送键 |
| 程序重启时账本仍是发送中 | 结果视为不明确，等待人工核实 |
| 云端人工核实未发送并补发 | 新的补发代号允许重新尝试；旧回执不能覆盖新尝试 |

OCR 只能核对客户端窗口内容。客户端本地气泡出现并不等同于腾讯服务端送达凭证；企微显示失败、网络状态异常或店长反馈未收到时，应人工核实。当前版本没有读取腾讯服务端送达状态的官方能力。

日志保存在 `sender-data/sender.log`，滚动保留 3 份、单份最多 1 MiB。日志记录任务编号和结果，不记录完整消息与令牌。`sender-data/deliveries.db` 是防重复账本，请与发送电脑配置一同保留。

## 登录后自动启动

确认手动发送端可以工作后，关闭手动运行窗口，执行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\install-sender-task.ps1
```

脚本创建名为 `Laike-WeCom-Sender` 的 Windows 计划任务，当前用户登录后运行；失败一分钟后重启，避免重复实例。不自动解锁桌面，也不代替企微登录。需要停止时，在任务计划程序中禁用任务，并结束该任务。只有确实运行该脚本才会安装计划任务，本次交付没有修改本机计划任务。
