# 数据源和发送工具接入

后台登录使用同源 Cookie。供外部程序调用的接口使用独立 Bearer 令牌；令牌可在后台“接入设置”查看，应用密钥不要写进 URL 查询参数。

## 抖音订单

服务端原生订单客户端使用：

- `POST https://open.douyin.com/oauth/client_token/` 取得应用访问令牌。
- `GET https://open.douyin.com/goodlife/v1/trade/order/query/` 按商户查询。
- 请求头 `access-token`、`Rpc-Transit-Life-Account`；查询参数 `account_id`、修改起止时间、`page_size=100`、`page_num=1`、游标。
- 从 `data.orders` 读取订单、`data.page.total` 读取总数、`data.search_after.CursorValue` 取后续游标；兼容 `order_list` 等同类封装。
- 已在真实接口观察到：时间窗内无订单时，`data` 可能只有 `error_code: 0` 和空 `description`，省略订单数组。程序将这一明确响应作为空页处理；无成功码、无效数组、有分页信息却缺少订单数组或未知结构仍会报错并保留同步位置。
- 平台错误码即使包装在 HTTP 200 中也视为失败，不推进该企业同步位置。令牌过期会刷新一次。

原始订单会转换为消息使用的字段。企业账号来自配置与订单商户信息的交叉核对；门店来自 `poi.poi_id` / `poi_id` / `intention_poi_id`，必须能匹配该企业内门店，否则等待人工分配。正式企业根商户 ID 按字符串保存，避免大整数损失精度。

平台批量解密适配预置路径 `/goodlife/v1/open/common_biz/crypto/decrypt/batch`，默认关闭，POST `account_id` 和 `encrypted_data_list`，按 `decrypted_data_list` 的密文与明文对应关系回填。此适配合同需要用实际服务商应用核对；没有权限或无法解密时保留其他订单信息，手机号缺失行按模板设置处理，不将 `Enc.` 密文作为号码。

公开订单接口文档：[订单查询](https://partner.open-douyin.com/docs/resource/zh-CN/local-life/develop/OpenAPI/general-capabilities/order.query/query)。当前文档未证明你的具体应用具备完整号码或独立留资读取权限。

## 独立留资接入

上游取得真实独立留资后调用 `POST /api/ingest`，使用后台的留资接入令牌：

```http
Authorization: Bearer INGEST_TOKEN
Content-Type: application/json
```

```json
{
  "type": "new_lead",
  "account_id": "100000000001",
  "poi_id": "200000000001",
  "record_id": "LEAD-20261012-0001",
  "event_time": "2026-10-12T10:30:00+08:00",
  "data": {
    "customer": "张女士",
    "phone": "13800000000",
    "intent": "面部补水护理",
    "source": "实际的留资表单来源",
    "remark": "希望周末到店"
  }
}
```

`account_id`、`poi_id` 应使用已在后台绑定的真实 ID。`record_id` 必须为该企业内稳定且唯一的留资编号，同一条留资重复提交只会生成一条通知。手机号使用上游在权限内提供的值；若仅有脱敏号码，可传脱敏号码；未提供则留空。

成功 HTTP 200 示例：

```json
{"duplicate":false,"queued":1,"message_id":123,"status":"pending"}
```

重复提交：

```json
{"duplicate":true,"queued":0}
```

`pending` 仅代表进入待发队列。只有发送端明确结果或人工确认后才会变为 `sent`。未知门店返回 `unrouted` 并保存正文，后台可将其分配到该企业内的门店。

该接口是本工具定义的标准接入口，不是未经验证的抖音原生回调地址。实际留资来源可能使用另一项独立平台能力，必须根据真实上游事件字段完成映射；本版没有把预约单或预订订单伪装成独立留资。

## 状态事件接入

同一个接入口支持稳定事件流补充状态变化：

```json
{
  "type": "status_change",
  "account_id": "100000000001",
  "poi_id": "200000000001",
  "record_id": "DY-20261012-0001",
  "event": "refunded",
  "event_id": "refund-event-unique-id",
  "event_time": "2026-10-12T11:00:00+08:00",
  "data": {
    "customer": "张女士",
    "phone": "13800000000",
    "goods": "面部补水护理套餐",
    "previous_status": "退款中",
    "current_status": "已退款",
    "refund_amount": "¥99.00"
  }
}
```

`event` 可为 `paid`、`verified`、`refunding`、`refunded`、`canceled`。必须提供稳定 `event_id`；同一事件重复传输用相同值。仅启用的状态事件会入队。状态事件数据中的金额已经是显示文本，订单原始数据中的金额则按后台设置的分／元单位转换。

若同时通过轮询和外部事件推送同一种状态，应选定一种通知来源，或让上游统一事件身份；不同来源、不同事件 ID 不会被系统擅自合并为同一个事件。

## 原始订单接入

同一接口也可接受原始订单，以复用原生订单归一化及去重：

```json
{
  "type": "order",
  "account_id": "100000000001",
  "data": {
    "order_id": "DY-20261012-0001",
    "merchant_info": {"account_id":"100000000001"},
    "poi": {"poi_id":"200000000001"},
    "sku_name": "面部补水护理套餐",
    "count": 1,
    "pay_amount": 9900,
    "order_status": 201,
    "create_order_time": 1791772200,
    "pay_time": 1791772230,
    "update_order_time": 1791772230,
    "contacts": [{"name":"张女士","phone":"13800000000"}]
  }
}
```

每次请求最多 2 MiB，较大批次应拆分逐条提交。时间可以为秒时间戳、毫秒时间戳或带时区的 ISO 时间；未带时区的字符串按北京时间解释。超过当前时间五分钟以上的业务时间会被拒绝。

## 已有发送工具的 HTTP 接口

后台选择“已有工具的 HTTP 接口”，填写地址和可选 Bearer 令牌。服务端发送：

```http
POST /send
Authorization: Bearer HTTP_TOKEN
Idempotency-Key: laike-业务事件哈希-r0
Content-Type: application/json
```

```json
{
  "id":123,
  "idempotency_key":"laike-业务事件哈希-r0",
  "lease_token":"本次尝试的随机标识",
  "lease_until":1791772400,
  "group_id":"发送工具提供的目标群ID",
  "group_name":"玥笙-辽宁-大连中山店",
  "text":"完整通知正文",
  "category":"new_order",
  "attempt":1,
  "is_test":false
}
```

发送工具必须持久保存 `idempotency_key`，防止重复请求再次发送。同步回执格式：

```json
{"status":"sent","group_id":"实际接收群ID","message_id":"远端消息编号","message":"已确认发送"}
```

| status | 必须满足的含义 | 云端处理 |
| --- | --- | --- |
| `sent` | 已确认执行，必须带实际 `group_id` | 已发送；群不一致则待核实 |
| `failed` | 明确确认没有发出，可以再次尝试 | 按退避规则重试，达到上限后失败 |
| `uncertain` | 可能已发送，尚不能确认 | 待人工核实，不自动重试 |
| `accepted` | 已接收，稍后回报发送结果 | 等待回执，超时转待核实 |

仅返回 HTTP 200、`{"ok":true}`、超时、连接中断或缺少明确业务回执均不会直接记为成功。请求不会自动跟随重定向。

异步工具用发送端接入令牌回报 `POST /api/relay/result`：

```json
{
  "message_id":123,
  "lease_token":"领取任务时的本次尝试标识",
  "status":"sent",
  "group_id":"实际接收群ID",
  "remote_id":"远端消息编号",
  "detail":"发送工具确认结果"
}
```

旧尝试的回执不能覆盖人工补发后的新尝试。人工补发会生成新的补发代号，且需要操作者先核实结果不明确的通知未发送。
