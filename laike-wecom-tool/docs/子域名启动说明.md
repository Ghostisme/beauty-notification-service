# 用子域名启动和访问工具

以下用 `1231.com` 作为主域名、`notify.1231.com` 作为工具地址演示。操作时换成自己实际持有的域名。本说明提供部署步骤，不代表已经修改线上 DNS、申请证书或部署阿里云实例。

当前已有 `notification.hongquanquan.cn` 的 DNS 和 HTTPS 时，按 [全流程第 7 节](部署实测与日常操作全流程.md#7-配置-https-后台入口) 复用现有站点，仅修改应用代理。无需重复执行本文的 DNS 添加与证书申请步骤。

从 GitHub 分支部署时，程序启动和密码文件路径按 [GitHub 分支部署说明](GitHub分支部署.md) 执行；本文第 2 节使用独立程序包路径。域名解析、HTTPS 和发送端连接方式相同。

最终后台地址为 `https://notify.1231.com`。新增 `notify` 记录即可，原来的 `www.1231.com` 可以继续访问原网站。子域名使用现有阿里云服务器，不需要单独购买一台服务器。

## 1. 添加域名解析

到管理 `1231.com` 的 DNS 控制台，在该域名下添加记录：

| 配置项 | 填写内容 |
| --- | --- |
| 记录类型 | A |
| 主机记录 | notify |
| 记录值 | 这台阿里云服务器的公网 IPv4 地址 |
| TTL | 默认值 |

主机记录填写 `notify`，记录值只填写公网 IP。记录中不填写 `https://`、路径或端口。解析生效后，`notify.1231.com` 指向该服务器。若域名使用其他 DNS 服务商，在实际管理解析的服务商处添加。

依据：[阿里云添加解析记录说明](https://help.aliyun.com/zh/dns/pubz-add-parsing-record)。

## 2. 启动工具服务

将程序包中的 `laike-wecom-tool` 文件夹放在服务器 `/opt/laike-wecom-tool`。以下采用随程序提供的 Docker Compose 方式，要求服务器已经安装 Docker 和 Compose 插件。

```bash
cd /opt/laike-wecom-tool
mkdir -p data
sudo chown 10001:10001 data
sudo chmod 700 data
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8790/health
sudo cat data/.bootstrap-password
```

健康检查应返回包含 `"status":"ok"` 的 JSON。管理员账号为 `admin`，初始密码在最后一条命令显示的文件中；修改管理员密码后，该初始密码文件自动删除。不要使用本地演示实例的密码作为正式部署密码。

Compose 已设置 `restart: unless-stopped`。Docker 服务设为开机启动后，工具会随 Docker 恢复运行。工具后台持续运行，无需保持 SSH 窗口打开。日常查看日志：

```bash
cd /opt/laike-wecom-tool
docker compose logs --tail=100 tool
```

若使用 systemd 方式部署，按 [阿里云部署说明](阿里云部署.md) 操作，保持只运行一种部署方式。

## 3. 配置网站入口和 HTTPS

阿里云安全组及服务器防火墙需要允许 HTTP 的 80 端口和 HTTPS 的 443 端口。应用的 8790 端口仅在服务器本机提供服务。

如果使用宝塔、1Panel 等服务器面板，在网站管理中为 `notify.1231.com` 新建独立站点，并配置反向代理：

| 配置项 | 填写内容 |
| --- | --- |
| 站点域名 | notify.1231.com |
| 反向代理目标地址 | http://127.0.0.1:8790 |
| HTTPS 证书域名 | notify.1231.com |
| HTTPS 跳转 | 证书申请并启用后，开启强制 HTTPS |

先让 HTTP 站点和解析生效，再通过面板申请并安装该子域名的 HTTPS 证书。证书启用后，用 `https://notify.1231.com` 登录后台。正式配置启用了安全 Cookie，HTTP 地址仅用于部署验证，后台登录应使用 HTTPS。

如果不用面板，可以使用 [Nginx 配置示例](../deploy/nginx.conf.example)。把其中的 `notify.example.com` 换成实际子域名，并填写已经存在的证书和私钥文件路径，再检查并加载配置。示例中的证书路径不会自动生成；尚未获得证书时，应先用 HTTP 站点完成证书申请，不要直接加载引用不存在证书的 HTTPS 配置。

域名区分由 Nginx 的 `server_name` 完成。已有其他网站时，新增这个站点配置，不覆盖其他网站的配置。

## 4. 连接发送端并开启自动任务

在 Windows 发送电脑的 `sender-config.json` 中，将 `server` 设置为 `https://notify.1231.com`，保存后重新启动发送端。也可以用 `sender.py --configure` 重新填写配置。该地址不加 `:8790`。

初始自动同步和自动发送均关闭。进入 HTTPS 后台，配置企业、门店、群对应关系和发送端，验证一条通知后，再启用需要的自动任务。云端监控后台与 Windows 发送端共同完成整条发送链路。

## 5. 验证入口

浏览器打开 `https://notify.1231.com/health` 应看到健康状态；打开 `https://notify.1231.com` 应看到工具登录页。确认 HTTPS 证书正常，并在后台查看发送端是否在线。

如果出现其他网站，核对该子域名的站点绑定；如果出现 502，核对工具是否运行以及代理目标是否为 `http://127.0.0.1:8790`；如果无法连接，依次检查 DNS、80/443 端口和 Nginx 运行状态。
