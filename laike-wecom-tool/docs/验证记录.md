## 资源测量

通过 `scripts/benchmark.py` 启动一个独立临时实例，经 HTTP 写入 1,000 条合成留资并生成 1,000 个待发任务。自动发送关闭，不访问抖音、不连接任何群。统计服务启动器及其实际 Python 子进程合计占用，结果见 `artifacts/benchmark.json`。

| 指标 | 本次本机观测 |
| --- | --- |
| 空闲内存 | 53.6 MiB |
| 写入期间观测内存 | 最高 54.1 MiB |
| 空闲 CPU | 0.78%，按一个逻辑 CPU 的计算口径 |
| 1,000 条数据入库及生成待发任务 | 30.52 秒，约 32.8 条／秒 |
| 概览接口平均响应 | 81.2 ms，5 次取平均 |
| 概览及最近 6 条通知响应合计 | 3,352 字节，未压缩，使用该测量数据集 |
| 数据库及即时相关文件 | 1,740,800 字节 |

这些是 Windows 本机结果，没有限制为 1 vCPU，也不包含操作系统、Docker、Nginx、Windows 桌面或 OCR 的内存。它们证明本机轻量服务的占用，不能当作阿里云实机容量承诺，也不能用入队速度代表企微实际发送速度。部署配置将应用限制为 384 MiB / 0.8 核，目标机器仍需按真实商户数量和订单量观察任务耗时。

静态页面资源约 67 KiB，不依赖远程字体或 CDN。页面不可见时不刷新，概览和通知列表每 10 秒刷新；发送端使用持久连接、群列表缓存和空闲查询退避。
