# 阿里云部署和维护

目标服务器：Linux，1 vCPU、2 GiB 内存、5 Mbps 带宽。服务端单进程、SQLite 本地文件，Docker 和 systemd 任选一种。Windows 企微发送端放在另一台常开电脑上。

如果从 `Ghostisme/beauty-notification-service` 仓库的 `feature/laike-wecom-tool` 分支部署，请先按 [GitHub 分支部署说明](GitHub分支部署.md) 拉取代码并使用 `/opt/beauty-notification-service/laike-wecom-tool` 目录。本文的 `/opt/laike-wecom-tool` 命令面向独立程序包；systemd 安装脚本要求该固定路径。

建议从默认的每 2 分钟同步一次开始，按企业依次查询。数据量和企业数增加后，查看后台任务耗时和错误，再调整间隔。程序不会启动重叠的同步任务。

## Docker Compose

将交付包解压到 `/opt/laike-wecom-tool`，服务器需已安装 Docker 与 Compose 插件。

```bash
cd /opt/laike-wecom-tool
mkdir -p data
sudo chown 10001:10001 data
sudo chmod 700 data
docker compose up -d --build
docker compose ps
sudo cat data/.bootstrap-password
```

账号为 `admin`。密码随机生成，修改管理员密码后初始密码文件自动删除。数据目录仅给容器用户 10001 写入；如果使用其他部署用户，请相应调整权限。

Compose 运行限制：内存 384 MiB、CPU 0.8 核、最多 64 个任务／线程，日志单文件 5 MiB、保留 3 份。应用镜像仅包含服务端，不安装 OCR、图形界面或 Windows 组件。健康检查每 30 秒访问 `/health`。

```bash
docker compose logs --tail=100 tool
docker compose restart tool
docker compose exec -T tool python manage.py check
docker compose exec -T tool python manage.py backup --retain 7
```

备份在宿主机 `data/backups`。每日自动备份可在当前部署账号的定时任务中加入以下一行，路径应与实际安装目录一致：

```cron
30 3 * * * cd /opt/laike-wecom-tool && /usr/bin/docker compose exec -T tool python manage.py backup --retain 7
```

## systemd

服务器需已安装 Python 3.12 和 venv 支持；Ubuntu 24.04 可通过系统包安装 `python3`、`python3-venv`。在程序目录执行：

```bash
cd /opt/laike-wecom-tool
sudo bash deploy/install-systemd.sh
sudo systemctl status laike-tool.service
sudo cat data/.bootstrap-password
```

脚本创建专用账号 `laike-tool`，安装独立 Python 环境、后台服务及每日备份定时器。仅对这个项目目录和其 `data` 工作。不要再同时启动 Docker 版本。

```bash
sudo journalctl -u laike-tool.service -n 100 --no-pager
sudo systemctl restart laike-tool.service
sudo systemctl list-timers laike-backup.timer
sudo -u laike-tool .venv/bin/python manage.py check
sudo -u laike-tool .venv/bin/python manage.py backup
```

## HTTPS 后台入口

正式实例只在 `127.0.0.1:8790` 监听。域名解析到服务器后，用 Nginx 转发 HTTPS 到该地址。可以使用服务器面板申请证书并设置反向代理，也可以按 `deploy/nginx.conf.example` 设置域名、证书路径。

对公网开放域名使用的 443 端口；使用证书申请或 HTTP 跳转时开放 80。后端 8790 不需要直接对公网开放。启动 Nginx 前检查配置有效性。

正式配置启用 `COOKIE_SECURE=true`，浏览器会话经 HTTPS 访问。使用 HTTP 直接访问时，浏览器不会回传安全 Cookie。如果仅在本机临时验证，可以给该临时实例设置 `COOKIE_SECURE=false`，通过回环地址访问。

示例 Nginx 配置启用静态资源及 JSON 压缩。后台不加载远程字体、组件库或图片；浏览器页面可见且停留在概览／通知记录时，每 10 秒刷新。Windows 端复用 HTTPS 连接、缓存群绑定并在空闲时放缓查询，降低按流量计费的开销。

## 配置任务

初始自动同步和自动发送均关闭。先添加企业和门店、填写抖音凭证、验证授权，再手动同步。企业之间的同步位置独立提交；失败企业保留原位置，下一轮重试。

默认首次回看 30 分钟，业务事件有效期 180 分钟；超过有效期的新接入历史事件标记为历史记录，不自动补发。已进入待发队列的通知会在发送恢复后继续处理，可以在后台取消或调整。长时间停机后按每天一段的窗口逐轮追赶。

核销／退款状态默认映射券维度的 401、301、300，分别对应平台的已履约、已退款、退款中。到店团购业务将已履约作为核销通知；如接入其他履约方式，需要按实际数据调整映射。系统不会仅凭订单状态“已完成”推断已核销。

当前订单及状态自动同步采用轮询，会在下一轮发现已观察到的状态变化；快速连续发生的中间状态可能无法从最终订单快照重建。若上游有完整、稳定的事件流，可通过标准事件接入口推送对应状态事件。

## 数据保留和备份

默认保留 90 天终态消息正文，后台可调。每天清理一次已发送、已取消、已关闭和历史通知的到期正文及尝试记录。失败、待核实、待分配、待发送任务不随终态清理删除。不含客户资料的业务事件哈希永久保留，以免历史同步再次发通知；数据库空页会复用，不自动执行耗时的整库压缩。

备份使用 SQLite 在线备份接口，包含：

- `tool.db`：门店、模板、业务快照、队列、审计与加密后的应用密钥。
- `.master-key`：解密应用凭证和校验后台会话需要的密钥。

两者必须一起保留。备份不包含 Windows 发送端账本；Windows 端的 `sender-data/deliveries.db` 和 `sender-config.json` 应在发送电脑维护时保留。备份默认只保留最近 7 份；请把需要的备份复制到另一处存储。

## 恢复

1. 暂停 Windows 发送端，停止云端服务。
2. 将现有 `data` 改名保存，创建新的 `data`，解压同一个备份中的 `tool.db` 与 `.master-key`，不要混用不同备份的数据库和密钥。
3. 恢复数据目录权限，先以自动发送暂停的状态启动。可在启动发送端之前进入后台关闭自动发送，检查恢复后的待发和待核实队列。
4. 运行 `manage.py check`，核对门店、模板和关键订单，再恢复发送端。

业务哈希组成发送去重标识，即使恢复较早备份后消息编号再次出现，也不会将不同订单误认为同一条已发消息。对于恢复前后可能已发出的任务，仍应核对本机账本及群消息。

## 更新程序

先备份，暂停自动发送，再替换源码及依赖锁文件；保留 `data`、Windows 端配置与账本。Docker 使用 `docker compose up -d --build`，systemd 在虚拟环境安装 `requirements.lock` 后重启服务。更新后检查健康状态、最新任务记录、门店路由及一条测试消息。

本次在 Windows 本地完成了服务运行和功能验证；本机 Docker 引擎不可用，因此没有宣称已完成 Linux 容器构建、阿里云实机运行或 Nginx 证书配置。配置文件可供部署复核，具体执行结果见验证记录。
