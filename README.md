# 抖音来客订单 → 微信群 同步工具

把抖音来客的订单信息**全自动**推送到**微信群**。支持**服务商模式**：一个应用服务多个来客商户，逐商户拉单推送，并解密订单中的客户手机号。

> 关于「微信群」的称呼：如果这个群的群主是企业微信成员、群里还有微信客户，企业微信把它叫「**外部客户群**」。它**在微信客户端里就是一个普通群聊**，所以本文统一按「微信群」处理，配置方式完全一样，不需要做任何区分。

## 推送目标：只推微信群，只有一条通道

唯一通道是 `target=outbox`：服务器只把文案写进「待发队列」，由你自己的微信号（`wx_relay.py`）从一台常开的电脑上发进指定微信群。**全自动**，不需要企业认证 / 可信域名 / 可信IP / ICP备案。

另外两条官方通道**做不成本需求**，这是平台硬限制，代码绕不过：

| 通道 | 能否用于微信群 | 原因 |
|------|--------------|------|
| 群机器人 Webhook | ❌ | 官方只支持企微**内部群**，外部群/客户群不支持 |
| 客户联系·企业群发 API | ❌ 不能自动 | 只是创建群发任务，**必须群主在手机端「群发助手」点确认**才真正发出；且每个客户群每天默认只收 1 条 |
| **微信号中继（outbox）** | ✅ 全自动 | 微信群在微信侧就是普通群，微信号能发就能自动发 |

`config.json` 的 `wecom.target` 代码里仍保留 `internal` / `customer_group` / `both` 作为**备用通道**（企业认证与备案走通后可切回官方接口），但后台页面已把它们折叠进「备用通道设置」，日常不用管。

> `outbox` 通道注意：客户端自动化属《微信个人帐号使用规范》之外的操作，有账号风险，建议用小号并控制频率。

## 两种数据来源

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `file` | 读取来客后台导出的订单 CSV/Excel | 快速上手，无需申请API权限 |
| `api`  | 服务商模式：client_token + account_id 逐商户拉单 | 全自动，多商户 |

## 快速开始（5 分钟把订单发进微信群）

1. 准备一个微信号（建议小号），让它**加入目标微信群**；在这台机器上登录微信 PC 客户端并保持运行（可最小化，不要锁屏休眠）
2. 拿到准确的群名（避免空格 / emoji 写错）：
   ```bash
   python wx_relay.py --list-groups      # 打印本机微信会话名，复制目标群名
   ```
3. 打开 `config.json`，把群名填到 `wecom.wechat_group`（`wecom.target` 默认已是 `outbox`）
4. 从抖音来客后台（订单管理 → 导出）下载订单表格，先预览文案：
   ```bash
   python sync.py --file 你的订单文件.csv --dry-run   # 只打印，不入队
   python sync.py --file 你的订单文件.csv             # 真实入队
   ```
5. 启动中继，消息自动发进微信群：
   ```bash
   python wx_relay.py --server https://notification.hongquanquan.cn --token 你的ADMIN_TOKEN
   ```

> 也可以用部署好的管理后台（`DEPLOY.md`）搭完整链路：后台点「🚀 推送」= 自动拉单 + 生成文案 + 入队，中继在另一台电脑上取件发送，全程无需人工。

## 服务商模式（多商户 + API 拉单 + 手机号）

### 前置条件

1. 在 [抖音开放平台服务商平台](https://partner.open-douyin.com) 创建**生活服务商应用**，拿到 `client_key` / `client_secret`
2. 控制台「解决方案」申请行业方案与能力权限（至少包含**订单查询** `life.capacity.order.query`）
3. **商家授权**：每个商户在抖音来客「店铺管理 → 第三方应用授权」授权你的应用；你在服务商平台「授权管理」确认授权关系
4. 拿到每个商户的**来客商户根账户ID（account_id）**

### 配置（config.json）

```jsonc
{
  "mode": "api",
  "douyin": {
    "client_key": "...", "client_secret": "...",
    "phone_decrypt": "local"
  },
  "merchants": [
    { "account_id": "商户1根账户ID", "name": "门店A",
      "wecom": { "webhook_url": "门店A的群Webhook" } },
    { "account_id": "商户2根账户ID", "name": "门店B" }
  ]
}
```

- 订单接口：`GET /goodlife/v1/akte/order/query/`（按 `update_order_start_time/end_time` 增量拉取，`sync.lookback_minutes` 控制时间窗）
- 每个商户独立去重（`state_<account_id>.json`），互不干扰
- 推送时逐商户执行：`python sync.py --api`（全部商户）或 `--merchant 门店A`（指定商户）

### 客户手机号

- 订单接口返回的购买人手机号是 **AES 加密密文**（平台隐私管控），脚本在订单原始结构中递归识别加密字段并解密
- **本地解密**（默认，`phone_decrypt: "local"`）：AES-256-CBC，key = clientSecret 补齐/裁剪至 32 字节（补位字符 `#`，左右交替补齐），IV = key 前 16 字节；需 `pip install pycryptodome`
- **官方接口解密**（`"api"`）：回退调用 `/goodlife/v1/open/common_biz/crypto/decrypt/batch/`；本地解密失败（缺依赖或解密异常）也会自动走此通道
- 手机号解出后填入订单 `phone` 字段；**`push.fields` 里含 `phone` 就在消息里展示（显示为「📞 联系电话」/「📱」），不含就不展示** —— 三种模板、汇总与每单一条模式统一遵守这个开关
- 解密失败不影响订单推送，手机号留空并打印日志
- 合规提醒：手机号属个人敏感信息，仅可用于核销/履约/售后等约定场景，注意个人信息保护义务

### 平台限制

- 接口/字段命名以官方文档为准，脚本已做常见字段兼容映射；若返回结构与预设不符，调整 `sync.py` 的 `map_api_order` / `PHONE_ENCRYPT_KEYS`
- 订单查询接口需申请权限并完成商家授权，未授权商户调用会返回权限错误

## 本地管理后台（Web 页面）

不想改 config.json 的话，用管理后台：页面即可完成「填商户 account_id + 微信群名 → 拉单预览 → 推送入队」全流程。

```bash
python web_admin.py          # 浏览器打开 http://127.0.0.1:8787
ADMIN_PORT=9000 python web_admin.py   # 自定义端口
```

功能：
- **商户管理**：新增/编辑/删除商户（account_id + 名称 + 微信接收群名，未填项继承全局）。企微那套备用通道设置已折叠在「备用通道设置」里，日常不用展开
- **订单数据**：拉单/推送时订单自动落库（SQLite，按 商户+订单号 幂等更新），支持按商户/关键词搜索、分页浏览
- **运行日志**：每次操作（拉单预览/推送/配置修改/各类错误）自动记录，手机号脱敏，可按商户/级别/操作筛选，错误含官方 logid 便于向平台反馈追踪
- **拉单预览**：调订单接口 → 解密手机号 → 生成消息模板，只看不发、不写去重状态
- **推送**：走去重后把文案写入「待发队列」，中继自动发到微信群；**推送测试**只打印不发送
- **待发队列**页签：查看/复制/重发/删除尚未发出的消息
- **链路测试**（在待发队列页签顶部）：一键往**测试群**塞一条测试消息，验证「服务器队列 → 微信号中继 → 微信群 → 回报」是否通了。不拉订单、不占用门店群（详见下文「先用测试群把链路试通」）
- **群绑定**（在待发队列页签顶部）：群被改名后，在这里一眼看出队列里还残留着哪些旧群名，并一键把消息重新绑定到当前配置的群名（详见下文「群被改名了怎么办」）
- **备用通道**（折叠区）：查企微客户群 chat_id、测试企微凭证

安全：
- 仅设置 `ADMIN_TOKEN`（环境变量或 config.json 的 `admin_token`）后，所有 API 需携带令牌，页面会提示输入；公网部署时**必须**设置
- 服务器部署（nginx + systemd，配合已解析域名）见 `DEPLOY.md`
- 注意：来客订单接口要求 **IP 白名单**，需在开放平台控制台添加服务器出口 IP，否则报 `2119013`

链路：`抖音来客拉单 → 手机号解密 → 消息模板 → 待发队列 → 微信号发出 → 微信群`。

安全说明：服务仅监听 `127.0.0.1`（本机访问）；config.json 中含密钥，不要提交到公开仓库；也可用环境变量 `DOUYIN_CLIENT_KEY` / `DOUYIN_CLIENT_SECRET` 覆盖来客凭证（优先级高于配置文件）。

## 唯一通道：用微信号把消息发到微信群（outbox + wx_relay.py）

适用场景：企业微信要求**可信域名备案主体与企业主体一致**（不一致时 `60020 not allow to access from your ip`），而 ICP 备案来不及；又需要把订单通知发到**客户群（普通微信群）**。

原理：服务器只负责把文案写进本地「待发队列」（SQLite `outbox` 表），你 Windows 电脑上的中继脚本轮询取件 → 用微信 PC 客户端发出 → 回报状态。全程不经过企业微信任何接口，因此**不需要企业认证、可信域名、可信IP、ICP备案**。

### 服务器端配置

1. 前端「商户管理」→ 把该商户的 **推送 target** 选为 `outbox`；
2. 填 **微信接收群名称**（必须与微信里的群名称**完全一致**）；
3. 点商户卡上的 **📤 只入队(零备案)**，或直接点「🚀 推送」（target=outbox 时只会入队）；
4. 顶部新增 **📤 待发队列** 页签可查看/复制/重发/删除。

也可命令行直接改 `config.json`：

```json
"wecom": {
  "target": "outbox",
  "wechat_group": "美业客户服务群"
}
```

### Windows 端中继

```bat
pip install wxauto requests
python wx_relay.py --server https://notification.hongquanquan.cn --token 你的ADMIN_TOKEN
```

常用参数：

| 参数 | 作用 |
|------|------|
| `--once` | 只跑一轮就退出（调试用） |
| `--dry-run` | 只打印不发送、不回报 |
| `--check` | 只检查微信客户端与令牌是否可用 |
| `--interval 60` | 轮询间隔秒数（默认 60） |
| `--limit 5` | 每轮最多发几条（默认 5，建议小批量） |

前置条件：Windows 上已登录**微信 PC 客户端**并保持运行（可最小化，不要锁屏休眠）；目标群已在你的微信里。不知道群名的准确写法就用 `python wx_relay.py --list-groups` 把会话名原样打印出来复制。

失败会自动重试，累计 5 次仍失败则标记 `failed`，可在「待发队列」页签手工重发。

> ⚠️ 风险提示：这属于客户端自动化操作，在《微信个人帐号使用规范》之外，存在账号被限制的可能。建议使用小号、控制发送频率、避免营销骚扰内容。若后续域名备案或企业认证通过，把 `target` 改回 `customer_group` 即可切换回官方通道。

## 目标群是企微里建的群（微信侧看起来就是普通微信群）

**你们的实际场景**：目标群是**门店群** —— 群成员 = 代运营方（你们） + 美业企业老板 + 店长；**客户不在此群里**，客户是通过抖音来客留资 / 下单的，微信群只是订单的接收点。这种群从**微信客户端**看就是一个普通群聊（企微称它为「外部客户群」，但微信不区分）。推送方式与普通微信群**完全一样**（`target=outbox` + 填群名），只是前置条件要多满足几条：

### 前置条件（三条，缺一不可）

1. **用来发送的微信号必须在该群里。** 群是企微那边建的，要让群主（或群管理员）把这个微信号拉进群（不要用主号，用小号）。
2. **群名要唯一且好认。** 建议统一按 **`品牌-省-市+门店`** 命名（示例：`玥笙-辽宁-大连中山店`，这是你们其中一个店的真实叫法）。重名时中继会直接报错而不是随便挑一个发 —— 宁可不发，也不能把 A 店的消息发进 B 店的群。
3. **该群没被设成「不显示该聊天」。** 不显示的会话不在会话列表里，脚本会报「会话列表里找不到该群」。

### 群名规范：`品牌-省-市+门店`

| 群名 | 说明 |
|---|---|
| `玥笙-辽宁-大连中山店` | 大连中山店的门店群（示例，你们其中一个店的真实叫法） |
| `玥笙-广东-深圳福田店` | 深圳福田店的门店群（同上的格式示意） |
| `抖音本地生活订单通知` | **测试群**（几个关键号都拉在里面），专门用来试链路 |

这么命名的三个用处：

1. **唯一、不重名** —— 中继按群名找群，重名会报错不发；
2. **一眼看出是哪家店** —— 出问题时不用问是哪家门店；
3. **可按规则批量匹配（可选）** —— 敏感信息提醒的关键词支持通配符（`*` = 任意多个字符，`?` = 正好一个字符）。这只是在你**确实需要**警觉「多个客户共存」时才用得上；本项目群内是自己的运营/老板/店长，该提醒已关闭。

### 先用测试群把链路试通（不动任何门店群）

「📤 待发队列」页签顶部有「🧪 链路测试」卡片：

1. 确认测试群名（默认读全局配置的 `wecom.test_group`，例如 `抖音本地生活订单通知`）；
2. 点「🧪 发一条测试消息」→ 服务器把一条测试文案写进待发队列；
3. 等中继下一轮（默认 60 秒）→ 去测试群里看一眼。

它**不拉订单、不占用任何门店群**，内容带毫秒级时间戳所以能反复点；收到即说明「服务器队列 → 微信号中继 → 微信群 → 回报」整条链路通了。用完了在待发队列里按 id 删掉那一条即可（界面上的测试按钮只删自己那条，不会碰门店消息）。

### 操作步骤

1. 后台「商户管理」→ 该商户的 **推送目标** 选 `outbox`（或命令行改 `config.json` 的 `wecom.target`）；
2. 拿准确群名（避免空格 / emoji / 全半角括号写错）：
   ```bash
   python wx_relay.py --list-groups      # 打印本机微信全部会话名，复制需要的那个
   ```
3. 把群名填进「**微信接收群名称**」，点「📤 只入队(零备案)」或「🚀 推送」；
4. 启动中继（同上一章）：
   ```bat
   python wx_relay.py --server https://notification.hongquanquan.cn --token 你的ADMIN_TOKEN
   ```

### 群被改名了怎么办（重新绑定）

群里可以随时改名（通常是企微群主在手机上改的，比如加个年份、改个门店名）。改名本身不影响后续推送，但要注意一件事：

**待发队列里的群名是「入队那一刻写死」的。** 群里一改名，队列里还没发出去的消息就还指着旧名字，中继会一直报「找不到群」，重试到上限后变成 `failed`。

**重新绑定只需要改一个字段：**

1. `python wx_relay.py --list-groups` 看到新群名；
2. 后台「商户管理」→ 该商户的「**微信接收群名称**」改成新群名 → 点「保存商户」。

保存的瞬间，该商户队列里**所有还指着旧群名的消息会自动改指到新群名**；已经 `failed` 的会被重置为待发、次数清零，中继下一轮就会重发。幂等键会跟着群名一起重算，所以重新拉单也不会重复入队。界面上会提示「群名已重绑定 N 条队列消息 → 「新群名」」。

**不想靠自动、或想先看一眼有没有漏网的**，去「📤 待发队列 → 🔗 群绑定」：

| 列 | 含义 |
|---|---|
| 配置的群名 | 商户当前绑定的群 |
| 已对齐（待发） | 队列里已经指向该群、等着发的条数 |
| 残留的旧群名 | 队列里还指着**别的**群名、发不出去的条数（含失败数）—— 这就是需要处理的 |
| 操作 | 「🔗 重新绑定」把这一商户的残留一次性改指到配置的群名；表头还有「全部重新绑定到当前群名」一次处理所有商户 |

> 边界：只动 `pending` / `failed` 的消息，`sent` 的历史记录保持原样（留痕）；只动**该商户自己**的队列，不会碰到其他门店。群名被清空时不会做任何动作。

### 中继的防「发错群」保护

客户群里发错内容是不可逆的，所以发送前做了三道校验，任一道不通过就**直接失败、不发送**（待发队列保留原消息，可在后台重发）：

| 校验 | 行为 |
|------|------|
| 群是否存在且唯一 | 会话列表里没有该群 → 报错并提示三条排查项；有两个完全同名群 → 报错，绝不随便挑 |
| 只有一个模糊命中 | 例如配 `玥笙-辽宁-大连中山店` 而列表里只有 `玥笙-辽宁-大连中山店客户群` → 采用并告警 |
| 切换后会话名核对 | `CurrentChat` 不是目标群 → 正文**不进入发送流程**（老版本 wxauto 无此 API 时自动降级，仅记日志） |

发送后还会尽力回读最后一条消息做内容比对，不一致只告警不重发 —— 回读失败不代表没发出去，若因此重试反而可能把同一条消息重复发进客户群。

### 与官方「企业群发」通道的取舍

| | outbox 中继（微信号发） | customer_group（企业群发 API） |
|---|---|---|
| 全自动 | ✅ 服务器入队 → 中继自动发出 | ❌ 只是创建任务，群主需在手机端「群发助手」手动确认 |
| 频次 | 无平台级硬限（自行控频防风控） | 每个客户群每天默认 1 条 |
| 前置门槛 | 一个小号 + 一台常开的 Windows 电脑 | 企业认证 + 可信域名/可信IP + ICP 备案主体一致 |
| 合规性 | 客户端自动化，有账号风险 | 官方接口，合规 |
| 适合 | 备案/认证卡住时的落地通道 | 认证通过后的长期正解 |

> 手机号展示与否**由你自己决定**：这些订单本来就是各自门店自己客户的，字段里想留 `phone` 就留着，`push.fields` 不做任何默认删减。系统只做一件事 —— 按【群名称】判断这个群是不是「多客户群」，是的话在控制台提一句醒，不拦截、不改内容。

## 备用通道（现在不用读）：企业群发 API / 内部群机器人

企业认证与备案走通之后，可以切回官方接口；在此之前这两条都满足不了「全自动推到微信群」：

| 通道 | 目标群 | 为什么现在不能用 |
|------|--------|-----------------|
| 群机器人 Webhook（`target=internal`） | 仅企微**内部群** | 官方不支持外部群/客户群 |
| 客户联系·企业群发（`target=customer_group`） | 企微客户群 | ① 只是创建任务，**群主必须在手机端「群发助手」手动点确认**；② 每个客户群每天默认只收 1 条；③ 需企业认证 + 可信域名/可信IP（域名备案主体需与企业主体一致），当前 60020 就是卡在这里 |

### 企业群发 API 的配置步骤（备用）

1. 企业微信管理后台 → **应用管理 → 自建应用 → 创建应用**，记下 `Secret`；「我的企业 → 企业信息」复制 **企业ID（corpid）**
2. 应用详情页确认应用有**客户联系**权限，且**应用可见范围**包含目标客户群的群主
3. 把 `corpid`、`secret` 填入 `config.json`（全局 `wecom` 或商户级 `merchants[].wecom`），`target` 改为 `customer_group`
4. 查询客户群 ID 并填入 `chat_id_list`：
   ```bash
   python sync.py --list-groups                  # 默认商户
   python sync.py --list-groups --merchant 门店A  # 指定商户
   ```
5. 试运行：`python sync.py --api --dry-run`

> 另有一条长期解法：企业微信主体与域名备案主体不一致时，可在手机端企微 → 帮助中心 → 自助申诉 → **可信域名验证申诉**，提交关联主体证明（母子公司/总分公司/同一集团/同一自然人控股）申请配置 —— 比等 ICP 备案快。

| 参数 | 作用 |
|------|------|
| `--file <路径>` | 指定订单 CSV/Excel 文件 |
| `--api` | 强制 API 模式（逐商户拉单） |
| `--dry-run` | 只打印消息内容，不发送（测试用） |
| `--all` | 忽略去重记录，全部重新推送 |
| `--serve` | 常驻服务模式（定时执行） |

## 配置说明（config.json）

- `wecom.target`：默认 `outbox`（微信群中继，全自动）；`internal` / `customer_group` / `both` 为备用通道
- `wecom.wechat_group`：**必填**，要收通知的微信群名，必须与微信客户端里显示的群名完全一致。各门店各填各的（`merchants[].wecom.wechat_group`），群名规范见上文「群名规范」
- `wecom.test_group`：**测试群名**，例如 `抖音本地生活订单通知`。「待发队列」页签的「🧪 发一条测试消息」只发到这里，不会误发到任何门店群
- `merchants[]`：多商户列表，每项 `account_id` + `name`，可覆盖 `wecom`/`push`；未配 `merchants` 时兼容旧的单商户配置（`douyin.account_id`）
- `douyin.phone_decrypt`：手机号解密策略 `local` / `api` / `off`
- `push.fields`：消息里展示哪些字段（订单号/商品/金额/状态/客户/**手机号**/时间/门店）。脚本不做任何默认删减，`phone` 要不要展示完全由你决定；`order` / `lead` 卡片模板、汇总模式、每单一条模式**都受这个列表控制**（号码解不出来时不留 `-` 占位行）
- `push.per_order`：`true` 每笔订单单独一条消息（实时感强）；`false` 汇总成一条（推荐订单多时）
- `wecom.privacy_multi_customer_keywords`：**多客户群关键词（可选功能，本项目已关闭）**。判断「这个群是不是坐着多个客户」的唯一依据：群名命中列表里任一条 → 提醒这批信息会被其他客户看到；不命中 → 不提示。**本项目实际场景是门店群（群内=代运营方+老板+店长，没有别的客户），已在 `config.json` 里显式置为 `[]` 关闭提醒**，手机号照常展示。支持通配符 `*` / `?`（不加通配符就是普通子串包含）；将来若真要发进多客户群，按你们的群名规律填词即可。可在 `merchants[].wecom` 里按商户覆盖
- `wecom.privacy_warn_fields`：命中多客户群时提示哪些字段，可选 `phone` / `customer`。本项目提醒已关，留空数组
- `sync.lookback_minutes`：API 模式每次拉取最近 N 分钟的订单
- 去重记录按商户分文件存储，同一订单不会重复推送

## 注意事项

- 走 `outbox` 时中继会控频（默认每轮最多 5 条、每条间隔 2 秒），订单量大建议用汇总模式
- **群改名不用重建队列**：改商户的「微信接收群名称」并保存，队列里还指着旧群名的待发/失败消息会自动改指到新群名（失败的重置为待发）。详见「群被改名了怎么办（重新绑定）」
- **敏感信息提醒是可选项，本项目已关闭**：该提醒只按**群名称**判断、不看消息内容（群名命中 `wecom.privacy_multi_customer_keywords` 才提示「这个群可能有多个客户、消息互相可见」）。但你们的实际场景是**门店群**——群里是代运营方 + 老板 + 店长，没有别的客户，客户是通过抖音来客留资/下单的，所以提醒没有意义，配置里已置为 `[]` 关闭，手机号照常展示。将来若真把消息发进了「多个客户共存」的群，再按群名填关键词即可（支持 `*` / `?` 通配符）
- 导出表格的列名如果和预设不一致（如"实付金额"写成了"支付额"），把新列名加进 `sync.py` 顶部的 `COLUMN_ALIASES` 即可
- API 模式的接口字段以来客开放平台文档为准，脚本已做常见字段名的兼容映射
